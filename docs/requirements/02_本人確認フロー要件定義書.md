# 本人確認（eKYC）フロー 要件定義書

> 作成日: 2026-04-16
> ステータス: ドラフト（レビュー待ち）

---

## 1. 概要

モデル登録ユーザーの本人確認（Know Your Customer）フローを定義する。
対面で会うマッチングサービスのため、安全性・信頼性の確保が最重要。

---

## 2. ビジネス要件

### 2.1 本人確認の目的

1. **安全性**: 対面サービスにおけるなりすまし・詐欺の防止
2. **信頼性**: 本人確認済みバッジによるマッチング率の向上
3. **法的対応**: 年齢確認（18歳以上）の確実な実施
4. **決済連携**: Stripe Connect の本人確認要件への対応

### 2.2 確認対象ユーザー

| ロール | 本人確認 | 備考 |
|--------|---------|------|
| モデル | **必須**（プロフィール公開の条件） | 対面で会うため安全性が最重要 |
| 画家 | **推奨**（任意だが確認済みバッジ付与） | 決済利用時は Stripe 側で KYC 必須 |
| 管理者 | 不要 | 内部ユーザー |

### 2.3 確認レベル

| レベル | 内容 | 用途 |
|--------|------|------|
| Level 1 | メール認証（実装済み） | アカウント作成 |
| Level 2 | 本人確認書類の提出 | プロフィール公開・応募 |
| Level 3 | 顔写真照合（書類 + セルフィー） | 将来的な信頼スコア向上 |

---

## 3. 本人確認方式の選定

### 3.1 方式比較

| 方式 | メリット | デメリット | 推奨度 |
|------|---------|----------|--------|
| **自前実装（書類アップロード + 管理者目視確認）** | 初期コスト低い・カスタマイズ自由 | 管理者の負荷大・セキュリティリスク・法的根拠が弱い | ★★★☆☆ |
| **Stripe Identity** | Stripe Connect と統合可能・AI自動判定・法的に堅い | 月額/件数課金あり・英語UIが一部残る | ★★★★★ |
| **TRUSTDOCK** | 国内特化・犯収法対応・日本語完全対応 | 初期費用+従量課金・API連携の開発工数 | ★★★★☆ |
| **Liquid eKYC（Liquid Inc.）** | 国内金融機関の実績多数・高精度 | 料金が高め・大規模向け | ★★☆☆☆ |

### 3.2 推奨方式

**フェーズ分けアプローチ:**

| フェーズ | 方式 | 理由 |
|---------|------|------|
| **MVP（初期リリース）** | 自前実装（書類アップロード + 管理者目視確認） | 開発コスト最小・すぐに始められる |
| **成長期** | Stripe Identity または TRUSTDOCK | 自動化・スケーラビリティ・法的対応強化 |

## 4. MVP（自前実装）の詳細設計

### 4.1 対応書類

| 書類種別 | 点数 |
|---------|------|
| 運転免許証 | 1点で可 |
| マイナンバーカード（表面のみ） | 1点で可 |
| パスポート（顔写真ページ） | 1点で可 |
| 健康保険証 + 住所確認書類 | 2点必要 |

### 4.2 提出フロー

```
1. モデルがマイページから「本人確認」を開始
2. 書類種別を選択
3. 書類の画像をアップロード（表面 + 裏面）
4. （任意）セルフィー撮影と書類の照合
5. 提出 → ステータスが「審査中」に変更
6. 管理者が管理画面で確認
7. 承認 → プロフィールに「本人確認済み」バッジ表示
   否認 → 理由付きで差し戻し、再提出可能
```

### 4.3 DB設計

| カラム | 型 | 説明 |
|--------|-----|------|

| document_type | string | drivers_license / my_number / passport / insurance_card |
| front_image_path | string | 表面画像パス |
| back_image_path | string(nullable) | 裏面画像パス |

| expires_at | timestamp(nullable) | 有効期限（書類の有効期限） |
| created_at | timestamp | |
| updated_at | timestamp | |

### 4.4 画面設計

#### モデル側

| 画面 | 機能 |
|------|------|
| 本人確認申請 | 書類種別選択 + 画像アップロードフォーム |
| 確認ステータス | 審査中 / 承認済み / 差し戻し（理由表示 + 再申請リンク） |

## 5. セキュリティ要件

| 項目 | 対策 |
|------|------|
| 画像保存 | `storage/app/private/identity/` に保存（publicアクセス不可） |
| 画像配信 | 署名付きURLまたは認証済みルート経由でのみ閲覧可能 |
| アクセス制御 | 管理者のみが書類画像を閲覧可能 |
| 保持期間 | 承認後6ヶ月で画像を自動削除（個人情報保護） |
| 暗号化 | ストレージ暗号化（サーバー側暗号化）を有効化 |
| ログ | 画像閲覧の監査ログを記録 |
| マイナンバー | マイナンバーカード裏面（番号面）は受け付けない旨を明記 |

---

## 6. 法的要件

| 項目 | 対応 |
|------|------|
| 個人情報保護法 | プライバシーポリシーに本人確認書類の取り扱いを明記 |
| 犯罪収益移転防止法 | 現時点では非対象（金融事業者ではない）だが将来の決済導入時に要検討 |
| 利用規約 | 本人確認の義務・虚偽申告時のアカウント停止を明記 |

## 7. 通知設計

| イベント | 通知先 | 方法 |
|---------|--------|------|
| 書類提出完了 | モデル | アプリ内通知 + メール |
| 審査開始 | モデル | アプリ内通知 |
| 承認 | モデル | アプリ内通知 + メール（「本人確認が完了しました」） |
| 否認 | モデル | アプリ内通知 + メール（理由 + 再申請の案内） |
| 新規申請あり | 管理者 | アプリ内通知 |

## 8. 将来の拡張（eKYC サービス連携時）

### Stripe Identity 連携案

```php
// Stripe Identity セッション作成
$session = \Stripe\Identity\VerificationSession::create([
    'type' => 'document',
    'options' => [
        'document' => [
            'allowed_types' => ['driving_license', 'passport', 'id_card'],
            'require_matching_selfie' => true,
        ],
    ],
    'metadata' => [
        'user_id' => $user->id,
    ],
]);
```

- Stripe Identity は Stripe Connect の KYC と統合可能
- 書類のAI自動判定（偽造検知含む）
- 料金: 確認1件あたり約500円（2026年時点）
