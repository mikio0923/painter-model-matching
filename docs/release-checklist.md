## 2. データベース設計の問題

### 🔴 JobApplication ステータスの不一致バグ

```
マイグレーション定義: status DEFAULT 'applied'
モデルコード・コントローラ: 'pending' を期待
→ 新規応募が全て「不明」ステータスになる
```

- **ファイル**: `database/migrations/2025_12_20_124242_create_job_applications_table.php`
- **対応**: マイグレーションのデフォルト値を `'pending'` に修正（または既存データをマイグレーション）

### 🔴 タイムゾーンが UTC のまま

- `config/app.php`: `'timezone' => 'UTC'`
- 日本向けサービスなのに全タイムスタンプがUTC表示になる
- **対応**: `'Asia/Tokyo'` に変更

### 🟠 ユーザー削除時のカスケード削除が危険

| テーブル | 問題 |
|---------|------|
| `messages` | ユーザー削除 → メッセージ物理削除（監査証跡消失） |
| `reviews` | ユーザー削除 → レビュー物理削除（評価履歴消失） |
| `job_applications` | モデルアカウント削除 → 応募履歴消失 |

- **対応**: ユーザーFKを `nullOnDelete()` に変更、または Soft Deletes を導入

### 🟠 不足しているインデックス

| テーブル | 不足カラム | 影響 |
|---------|----------|------|
| `job_applications` | `model_id` | モデルの応募一覧取得がフルスキャン |
| `messages` | `sender_id`, `receiver_id` | スレッド取得が低速化 |
| `reviews` | `reviewed_user_id` | 評価一覧取得が低速化 |
| `favorites` | `(favoritable_id, favoritable_type)` | ポリモーフィック検索が低速化 |

### 🟠 不足しているDB制約

- `reward_min <= reward_max` の CHECK 制約なし（逆転値が保存可能）
- `reward_min >= 0` の CHECK 制約なし
- `model_profile_images` テーブルに `timestamps()` がない

### ⚪ Soft Deletes が主要テーブルに未実装

- `User`, `Job`, `ModelProfile`, `Review` 等に `SoftDeletes` トレイトがない
- 誤削除からのリカバリが不可能

## 3. サーバー・インフラの問題

### 🔴 本番環境構成が存在しない

- `docker-compose.yml` は開発専用のみ。本番用が一切ない
- 以下が未検討:
  - HTTPS / SSL証明書（Let's Encrypt 等）
  - 本番用 Nginx 設定（gzip圧縮、キャッシュヘッダー等）
  - 静的アセットのCDN配信
  - コンテナオーケストレーション（ECS / GKE / Fly.io 等）
  - オートスケーリング設定

### 🔴 本番環境の設定が開発用のまま

```env
APP_DEBUG=true            # → 本番では false 必須（スタックトレース露出）
SESSION_SECURE_COOKIE=false  # → 本番HTTPS環境では true 必須
APP_LOCALE=en             # → ja に変更
APP_NAME=Laravel          # → サービス名に変更
MAIL_HOST=mailhog         # → 本番メールサービス（SES / SendGrid等）に変更
```

### 🔴 認証情報のハードコード

- `docker-compose.yml` にDB接続パスワードがハードコード
- `.env` の `DB_PASSWORD=secret` が直書き
- **対応**: 本番用シークレット管理（AWS Secrets Manager / Vault等）の設計・導入

### 🟠 メール認証が無効化されている

- `User.php` の `MustVerifyEmail` がコメントアウト
- ユーザーはメール認証なしでログイン可能
- **対応**: 実装を有効化しメール送信フローを整備する

### 🟠 Docker 本番構成の不備

- ヘルスチェック定義なし（サービス起動順序制御が不安定）
- `restart: unless-stopped` ポリシーなし（クラッシュ後に自動復帰しない）
- リソース制限（memory / CPU）なし
- MailHog サービスが本番に混入する可能性

### ⚪ 監視・アラート設定が未定義

- エラーログ収集（Sentry 等）なし
- レスポンスタイム監視なし
- DBパフォーマンス監視なし

- Bladeテンプレートでの `{{ }}` 使用状況を確認（`{!! !!}` の使用箇所に注意）
