> ステータス: ドラフト（レビュー待ち）

## 1. 概要

本サービスにおけるメール通知の全体設計を定義する。
現状はアプリ内通知のみで、メール通知は会員登録確認の1種類だけ実装済み。

## 4. 技術設計

### 4.1 メール配信サービス選定

| サービス | メリット | デメリット | 推奨度 |
|----------|---------|----------|--------|
| **Amazon SES** | 低コスト(0.1$/1000通)・Laravelネイティブ対応 | 初回のサンドボックス解除申請が必要 | ★★★★★ |
| **SendGrid** | 無料枠100通/日・テンプレートエディタ付き | 有料プランが割高 | ★★★★☆ |
| **Mailgun** | 開発者向けAPI充実・ログ管理優秀 | 無料枠なし | ★★★☆☆ |
| **Resend** | モダンAPI・React Emailテンプレート対応 | 比較的新しいサービス | ★★★☆☆ |

**推奨: Amazon SES**
- Laravel の `config/mail.php` で `MAIL_MAILER=ses` のみで設定可能
- 本番インフラがAWSの場合、追加サービス不要
- 月間62,000通まで無料（EC2から送信の場合）

### 4.2 アーキテクチャ

```
[イベント発生]
    ↓
[NotificationService] ← 既存のアプリ内通知サービス
    ↓
[Mail Queue (database driver)]
    ↓
[Queue Worker が非同期送信]
    ↓
[SES / SendGrid]
    ↓
[ユーザーの受信箱]
```

### 4.3 キュー設定

```env
# .env
QUEUE_CONNECTION=database
MAIL_MAILER=ses
MAIL_FROM_ADDRESS=noreply@palette.example.com
MAIL_FROM_NAME="Palette"
```

```php
// メール送信は必ず Queue 経由で非同期
Mail::to($user)->queue(new ApplicationReceivedMail($application));
```

## 5. メール配信設定（オプトアウト）

### 5.1 DB設計

#### `email_preferences` テーブル（新規作成）

| カラム | 型 | 説明 |
|--------|-----|------|
| id | bigint PK | |
| user_id | bigint FK | |
| application_emails | boolean default true | 応募関連メール |
| message_emails | boolean default true | メッセージ通知メール |
| review_emails | boolean default true | レビュー通知メール |
| reminder_emails | boolean default true | リマインダーメール |
| marketing_emails | boolean default true | お知らせ・プロモーション |
| created_at | timestamp | |
| updated_at | timestamp | |

### 5.2 配信停止フロー

```
1. メールフッターの「配信停止」リンクをクリック
2. 署名付きURL → メール設定画面（ログイン不要）
3. カテゴリ別にON/OFF切り替え
4. 「すべて停止」ボタンも用意
```

### 5.3 実装

```php
// メール送信前にプリファレンスをチェック
if ($user->emailPreference?->application_emails !== false) {
    Mail::to($user)->queue(new ApplicationReceivedMail($application));
}
```

## 6. メッセージ通知の頻度制御

メッセージ受信メールはチャット的に連続するため、頻度制御が必要。

| ルール | 説明 |
|--------|------|
| バッチ送信 | 同一スレッドの未読メッセージは5分間バッファリング後にまとめて1通で通知 |
| 最大頻度 | 1ユーザーあたり1時間に最大3通 |
| オンライン判定 | 直近5分以内にアクセスがあるユーザーにはメール送信しない |
